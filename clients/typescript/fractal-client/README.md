# Fractal TypeScript client

`Models.generated.ts`, `Client.generated.ts`, and `Schema.generated.ts` come from the normative client v0 schema and operations manifest. Edit `crates/fractal-client-codegen/src/main.rs`, `crates/fractal-client-codegen/templates/Client.ts.in`, or the rich emitter in `crates/fractal-client-codegen/src/rich.rs`, then run `cargo run -p fractal-client-codegen`. The generator's `--check` mode compares all generated bytes without writing files.

The package exports TypeScript source with explicit `.ts` relative import specifiers. NodeNext
consumers use `allowImportingTsExtensions` for no-emit checking, or
`rewriteRelativeImportExtensions` when emitting JavaScript.
The generated source uses erasable TypeScript syntax, and the package type checks enforce
`erasableSyntaxOnly` and `exactOptionalPropertyTypes` for both the raw client and rich schemas.
The raw client also type checks with `verbatimModuleSyntax`.

The client uses standard `fetch`, so callers can supply a fetch implementation and a credential callback. Call `discover()` before rendering capability-dependent controls. List and event limits are checked against the server's advertised bounds. Submit fenced actions with the generated typed methods, then use `followOperation(operation_id)` for accepted actions. `terminalStream` opens the screen stream a `terminal.attach` capability allows and calls `onScreen` with each changed screen; it needs a WebSocket that accepts headers, such as React Native's, or a `socket` factory. `collectionStream` opens the one collections socket: `subscribe` holds a window of missions, attention, agents, or work, `subscribeTerminal` follows a terminal with its attach capability, and `subscribeConversation` follows an agent's or a session's conversation, each by a client-chosen ID; `onFrame` receives every frame. `applyWindow` folds `snapshot` and `changes` frames into a window's ordered rows. Commands sent before the socket opens wait for it.

The default transport binds `globalThis.fetch` to `globalThis`, preserving the receiver required by browser implementations. Supplying `fetchImpl` overrides that default without rebinding the custom implementation.

HTTP rejections with a non-JSON body (for example, a middleware body-limit 413) throw
`ClientError` with code `http-error`, the HTTP status and status text, and
`retryable: false`. `Retry-After` remains available as `retryAfterMs`. Valid JSON
error envelopes retain the server's code, message and details regardless of the
response content type. Malformed JSON in a successful response and response-body
read failures are not converted to HTTP errors.

Every HTTP method accepts a final optional `RequestOptions` argument (`{ signal?: AbortSignal }`).
Existing query options and optional defaults keep their positions: for example,
`runtimesGet(id, { signal })`, `messageSend(input, { signal })`, and
`resourcesList(filters, pageOptions, { signal })`. Cancellation is checked before fetching
and after asynchronous credentials/discovery; the signal stays attached to native fetch while
the JSON body is consumed. Cancellation does not prove an action was not delivered and never retries it.

Shared action delivery distinguishes certainty from transport errors. Only explicit
`applied: "none"` in the outer error or its details, with no unknown or malformed
contradiction, proves nonapplication. Bare stale-fence, rate-limited, other HTTP errors,
network failures and malformed receipts after dispatch remain `unconfirmed`.
`failed` means a pre-dispatch build failure or a proven nonapplication refusal;
`sent` requires the send adapter's completion check to succeed.
`sendAction` may rebuild only after proven nonapplication. Neither automatic delivery
nor `resendAction` / `resendBoundAction` POSTs an unknown retained attempt, refreshes
its fence, or rebuilds/re-signs it. The retained packet and original member are for
reconciliation, not permission to resend. This is process-lifetime retention, not a
durable outbox or a read-only server outcome endpoint.

Focused certainty and pure client tests use the existing workspace Vitest dependency:
`CI=1 node_modules/.bin/vitest run --config clients/typescript/fractal-client/vitest.config.ts`
from the repository root.

The pure outbox core is exported from `@fractal/client/outbox`, and packet preparation
from `@fractal/client/prepared-packet`. Web and native consumers must import their
values and types from these subpaths, not `@fractal/client`: the root intentionally
does not re-export write-path helpers, keeping them outside the SDK's eager read graph.
These modules provide no storage adapter, startup worker, signing service, or server
reconciliation endpoint:

- `OutboxRepository<TPacket>` binds `commit`, revision-based `compareAndSwap`,
  `list`, and `read` permanently to an original principal/deployment/member scope.
  Successful writes mean durable transaction completion; adapters must reject
  storage failures rather than silently fall back to memory.
  Derive its deployment identity with `outboxDeploymentId(issuer, issuerKey)`,
  the JSON-encoded tuple of the captured issuer and issuer key.
- `createOutboxRecord(id, intent)` accepts immutable serializable intent (text and
  attachment references carrying content hash, optional name, media type and a
  storage reference) as pending/preparing, with no packet. Commit this record before
  acknowledging local acceptance, uploading attachments or preparing the request.
- `prepareOutboxRecord(record, packet, expectedIdentities)` proposes pending/ready
  only from preparing. Persist it by revision CAS; the packet cannot be replaced
  afterward. Persist `markOutboxDispatched` using CAS before making the single POST;
  preparing cannot dispatch, and only the successful CAS owner may dispatch.
- Adapters must call `isAllowedOutboxTransition(previous, next)` **inside** their
  CAS transaction. It accepts only revision-incrementing transitions produced by
  the pure core and rejects changed intent/packet, wrong revisions and fabricated
  certainty changes, including unknown-to-not-applied.
- `observeOutbox` records a validated completed receipt, explicit nonapplication,
  unknown, or an exact timeline identity match. Pass `appliedAnswer(error)` for
  failure evidence; validate completed receipts against the original packet first.
  Earlier ambiguity survives a later refusal and serialization, and unknown never
  regains dispatch permission. Delivered records retain receipt or timeline evidence.
- `restoreOutboxRecord` retains never-dispatched pending attempts, including
  preparing records whose owners resume uploads/preparation from retained intent.
  Dispatch-marked nonterminal records become unknown even if a crash happened
  before the socket call. Persist changed restoration/observation records by
  revision CAS. Definitive delivery and unambiguous nonapplication remain terminal.
- Repository `list()` returns tagged `OutboxEntry` values: `{ _tag: 'record', record }`
  or `{ _tag: 'corrupt', id, revision? }`. Restore the list with
  `restoreOutboxEntries`; it applies normal restoration only to valid records and
  preserves every corrupt entry as persistent unknown recovery, never a fabricated
  record. Display **storage damaged; delivery unknown** and offer only explicit
  Discard. Copy is unavailable without trustworthy content; Send/Retry and automatic
  expiry are never allowed. The reference memory repository lists only record entries.
- `prepareMessageSendPacket`, `prepareThreadStartPacket`, and
  `prepareThreadReplyPacket` return complete serializable action POST bodies.
  Supply the original ID, key, fence and all prepared parameters; persist the
  returned body rather than a send closure. Existing signatures pass through
  unchanged; authorized unsigned web bodies remain unsigned. Preparation performs
  no signing, transport selection or ID generation. Submit the retained packet
  unchanged through `submitAction` only when the core permits dispatch.
- `expectedPreparedPacketIdentities(packet, sender, sha256)` derives the message
  identities to persist with the record. Supply the captured original authenticated
  sender, not the current connection's actor; unsigned thread bodies do not encode
  their sender. Supply the platform's SHA-256 implementation. Chat hashes the key;
  thread messages use the canonical sender/thread/action/key scope and two hashes.
  A thread ID alone is never proof that this Start or reply was delivered.
- Unknown reconciliation is a **person-initiated status check**, never an automatic
  replay. After an authoritative timeline read on the original member, submit
  `{ kind: 'observed', source: 'timeline', identity }` only for an actually present
  message identity. The core settles delivery only when it matches a retained
  expected identity. A mismatch leaves unknown unchanged; absence has no observation
  variant and never proves nonapplication or permits another POST.

`OutboxRepository<PreparedPacket>` is the shared adapter boundary. Concrete browser
and native repositories, acceptance UI, and dispatch owners must implement these
durability barriers; importing this pure module alone does not persist messages.

Tests can import `createMemoryOutboxRepository` from `@fractal/client/test-support`.
This shared reference double is scoped, isolates snapshots with copy-on-read/write,
and calls `isAllowedOutboxTransition` inside its synchronous CAS check/write section.
It models transaction ownership and refusal behavior but is **not durable** and must
never replace a production IndexedDB or native storage adapter.

The manifest read ids `harness-questions.list` and `harness-questions.get` map to
`harnessQuestions(queryOptions, requestOptions)` and `harnessQuestion(id, requestOptions)`;
their public helper names do not include the manifest's `list`/`get` suffixes.

`collectionStream` resolves to the pre-open command surface. Its optional `onOpen` callback
reports actual WebSocket readiness once, before buffered commands flush. Commands issued inside
`onOpen` queue behind prior commands, preserving cancellation and replacement order. Closing or
throwing during `onOpen` discards the queue. Known frame envelopes
are structurally validated before `onFrame`; resource rows and timeline entries remain raw for
tolerant per-row decoding. Unknown kinds and additive fields remain available to consumers.
Malformed framing and exceptions from `onFrame` or `onOpen` close the socket and reach `onEnd(error)`
once instead of escaping the WebSocket event handler.

Create a new folder-only arrangement using `arrangementEdit` with `parameters.version: 2`;
omitting the version keeps v1 creation. `ArrangementBody` is a version-discriminated v1/v2
union, including strict rich-schema decoding. `arrangementMembershipEdit` accepts typed
place/remove operations (`bucket: null` means root). `arrangementsMemberships` takes the
arrangement's person name and UUID plus its owning `person/NAME`, returning a typed
snapshot-bound keyset page. `subscribeOrderedMemberships` requires person and arrangement
subject and follows lifecycle-aware held-window changes. Existing v1 placements are not
implicitly migrated.
Narrow collection frames by `collection === "ordered-memberships"` before passing them to
`applyWindow` with a `CollectionWindow<OrderedMembership>`; those rows expose the member and
position directly, and the window keeps the frame's required `membership` state for the whole
container, replacing it even when a `changes` frame leaves rows and order alone.
`membership.changed_index` is an opaque host-local invalidation frontier scoped by
`snapshot.host_id`, not a canonical revision or cross-host value. Other collections keep
resource windows without membership state. Rich-schema decoding validates membership frames
and response envelopes, including empty pages, as disjoint variants.

## Native Fabric transport

Node and Bun callers can use the native subpath without changing browser or React
Native imports:

```ts
import { createFabricClient } from '@fractal/client/fabric'

const client = await createFabricClient({
  endpoint: 'fabric://studio/st3-client-v0',
  credential: () => credential,
})
const capabilities = await client.capabilities()
```

The native adapter invokes the local `fabric` executable, resolves a unique
trusted peer name without regard to ASCII case, and sends HTTP and client
WebSockets through the returned Unix tunnel socket. An explicit NodeID bypasses
peer-name lookup. It does not start a TCP proxy or forward trusted-local person
headers. Pairing credentials and signing requirements remain gateway-owned.

The Rust and Node native readers accept exactly `fabric://<NodeID-or-name>/st3-client-v0`
and `fabric://<NodeID-or-name>/fractal-client-v0`. Both dial the exposed
`st3-client-v0` gateway service; endpoint formatting and gateway defaults still use
`st3-client-v0`. Other service names, URI suffixes and trailing line breaks are rejected.

The native TypeScript adapter recognizes canonical hex/base32 NodeID syntax and
leaves Ed25519 key validity to Fabric. Unlike the Rust adapter's exact identity
parser, it does not fall back to peer-name lookup for a syntactically valid but
invalid-curve key. Such a target fails closed at the Fabric dial; use an ordinary
unique trusted name or a valid NodeID instead.

Keep the optional `ws` dependency installed for native WebSocket streams. The
`@fractal/client` browser/phone entry point does not import Node modules or `ws`;
those runtimes continue to use the existing authenticated HTTP(S) transport.
`program` can select an explicit Fabric executable for isolated installations.
Only `/v1/client/` and `/v1/health` routes are valid over the native adapter.

## Active span propagation

Fractal, web, and React Native callers can pass their active span context without
adding a runtime dependency to this SDK. For example, an app already using
`@opentelemetry/api` can configure:

```ts
import { context, trace } from '@opentelemetry/api'
import { FractalClient } from '@fractal/client'

const client = new FractalClient({
  baseUrl: daemonUrl,
  traceContext: () => {
    const span = trace.getSpan(context.active())?.spanContext()
    if (!span) return undefined
    return {
      traceparent: `00-${span.traceId}-${span.spanId}-${span.traceFlags.toString(16).padStart(2, '0')}`,
      tracestate: span.traceState?.serialize(),
    }
  },
})
```

The synchronous callback is read once per HTTP request or WebSocket open, not at
client construction, so each call continues the currently active span. An absent
callback or `undefined` result sends no trace headers. Invalid `traceparent`
values (non-lowercase W3C format, version `ff`, or zero trace/span IDs) suppress
both headers. `tracestate` is forwarded verbatim; the SDK never adds `st=c`.
A daemon with trace propagation records `st.parent.sampled` for a sampled
incoming parent without an `st` tracestate entry, so the collector can honour
external app sampling decisions. Daemons without trace propagation ignore both
headers.
Web streams require a header-capable `socket` factory: the browser's native
WebSocket API cannot set these headers.

Collection subscribe commands additionally carry `trace: { traceparent, tracestate? }`, captured when the subscribe is issued rather than when a queued command flushes; daemons ignore unknown command fields.

`client.withTraceContext(callback)` returns a view whose requests and streams carry that callback's context instead, sharing credentials, transport, and discovered capabilities with the original. Use it when one call has its own span, since an asynchronous call reads the callback after its first `await`.

Browser `WebSocket` cannot set headers. A browser socket factory must move the context it receives in `headers` to the `traceparent`/`tracestate` URL query parameters, which the Fractal gateway validates and strips before forwarding.

## Rich Effect schemas

Import `@fractal/client/schema` (or `Schema.generated.ts` directly) for Effect 4 `Schema.Struct` codecs and their `typeof X.Type` decoded types. Rich consumers must provide the pinned `effect@4.0.0` stable peer dependency. The raw client entry point does not import Effect, so existing fetch/Expo consumers need no dependency or API migration.

Use `@fractal/client/schema/read` for non-terminal read/query responses and collection streams.
Its generated import graph constructs no mutation request/result/parameter or PTY screen/session
validators, without relying on tree shaking. Terminal resource metadata remains available for
roster/resource reads. Terminal screen/content and mutation codecs stay on `@fractal/client/schema`,
which retains all existing exports and re-exports the same read validator instances. Shared codec
support preserves strict decoding and unknown-case tracking across both entrypoints. Regeneration
also writes `ReadSchema.generated.ts` and `SchemaSupport.generated.ts`; never edit them directly.
`ReadCollectionCommand` and `ReadCollectionFrame` cover collection/conversation stream branches
without terminal subscriptions/screens; the original complete unions remain on the full surface.

```ts
import * as FractalSchema from '@fractal/client/schema'

const unknown = FractalSchema.decodeUnknownSync(FractalSchema.ErrorCode)('future-error')
// { _tag: "Unknown", raw: "future-error" }; encoding restores the wire string.
const strictDecode = FractalSchema.decodeUnknownEffect(FractalSchema.ErrorCode, 'strict')
```

The synchronous and effectful decode helpers default to tolerant mode: unknown enum values survive as `UnknownCase`, excess struct keys are ignored, and `null` on an optional nonnullable field becomes absence. Strict mode rejects unknown enum cases, excess struct keys, and those optional nonnullable nulls. Declared nullable fields decode to `Option` in both modes; optional nullable fields equate missing with null, and `None` encodes as null. Required nonnullable fields reject null in both modes. Arbitrary JSON bags are not interpreted as unknown enum cases merely because they contain `_tag` and `raw`.

Object constraints beside `oneOf` apply to every generated branch, including shared required fields and discriminators. Tolerant decoding may ignore future keys, but does not relax those shared constraints or forbidden branch fields; a capabilities response cannot also decode as a pairing challenge.

Source break for general pairing callers: `PairingBegin` and `PairedSession` are now untagged unions (`PersonPairingBegin | AssistantPairingBegin`, `PersonPairedSession | AssistantPairedSession`), so callers that read `person_id` or person-only fields off the generic types must narrow to the person variant first; `person_id` is optional on shared projections such as `Device`. Person-only callers can switch to the `PersonPairingBegin`/`PersonPairedSession` types and keep their existing shape. The Rust person variants enforce `deny_unknown_fields`.

Inline semantic keywords provide branded strings and subject references, UTC instants, durations, and redacted credentials. Integer codecs reject unsafe JavaScript integers on decode and encode. Duration codecs round to whole wire units on encode; second durations preserve exact safe-integer units without overflowing millisecond precision. Recursive Glass layouts remain validated through suspended schemas.
Subject-reference schemas retain authored string-length bounds as well as their family identity checks.

After the root frozen install, run the focused rich checks with:

```sh
pnpm --filter @fractal/client run test:schema
pnpm --filter @fractal/client run typecheck:schema
```
