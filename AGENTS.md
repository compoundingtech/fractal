# Repository instructions

## Fix causes; do not hide broken paths

Fix the cause of a slow or broken path. Do not add fallbacks, retries, caches or timeouts that hide it. A workaround that makes the symptom disappear while leaving the defect in place is not an acceptable fix.

Retries for peers and networks are valid because those connections can be unreachable by nature. Keep that distinction explicit; retries must not hide a defect in a local path.

Build reactive behavior instead of polling. Use incremental view maintenance when necessary to keep updates and reads efficient.

Nathan approved this policy on 2026-10-06. See issue #1566 and st document doc/fleet/smalltalk/no-workarounds/hunt-2026-10-06 for examples.

## Public history: every introduced commit must be clean

`public-repo-history` is an ordinary content check, separate from test evidence. It catches honest mistakes; it is not yet a forgery-proof admission boundary. Its workflow is ready for a separately activated organization required-workflow rule, but that trust-anchor decision remains open; see [CI](docs/ci.md#required-public-history-guard). Hosted scanning loads `scripts/check-public-repo` and policy from `github.workflow_sha`, which is only an approved protected revision when a trusted required-workflow rule selects it. Without that rule a candidate can change its workflow or scanner. The local hook uses the accepted remote main's scanner. Immutable event `BASE` and `HEAD` define the history range: every commit in `merge-base(BASE, HEAD)..HEAD`, recursively including merged side histories and merge commits. For every commit it checks the commit message and complete introduced blobs at their real paths: additions, modifications and type changes relative to every parent, not removed lines or synthetic diff headers. Gitlinks receive path checks, not blob-content checks. A dirty intermediate commit still fails after a later commit removes the offending content: a clean head tree is not clean history.

`scripts/install-git-hooks` installs a lightweight, blocking content-only pre-push guard before the existing evidence-signing path. It uses the trusted base's scanner; it does not build, test or sign the candidate. `ST_SKIP_EVIDENCE=1` and `ST_EVIDENCE_LOCAL=off` affect only evidence signing and never skip the content guard. Skipping the hook is not an approved publication path. The ordinary hosted check is not a substitute for a forgery-proof trust anchor.

If introduced history is dirty, create a replacement branch from a clean base, apply only public-clean changes with public-clean commit messages, and open a replacement PR. Do not force-push or rebase the existing PR to hide the dirty commits, and do not expect a cleanup commit to repair its history. Keep private identities, machine paths and fleet configuration out of authored content. See [the CI history contract](docs/ci.md#required-public-history-guard).

## Evidence: run the tests, they sign

`scripts/install-git-hooks` (run by the default `nix develop` shell outside CI, which prints one line the first time) installs a pre-push hook. After the blocking content guard passes, when you push the branch you have checked out and its head tree has no signed evidence yet, the existing evidence path runs the required checks that have a local command (`scripts/fractal-test`) on this machine, the host's signer records them, the notes are pushed, and then the push goes. Evidence failures never block a push: every failure is printed and the push goes. The hook and the runner are **not** read from the tree you push: the stub runs `scripts/evidence-prepush` and the self-contained `scripts/st-test` implementation as they are on `origin/main`. The checks they run (`nix develop`, `pnpm install`, the tests, in a clean worktree of the pushed commit) are the tree's code and run on your machine as you, with the host's signing key within reach: that is what testing it means here (our own machines are trusted; known defect 22).

Keep human commands and diagnostics at `scripts/fractal-test`. During `arn:lmig:smalltalk:2026-10-27-st-test-shim`, that file is an executable Python exec shim to adjacent `scripts/st-test`; base readers copy and run only the self-contained `scripts/st-test`, and internal module loaders import it rather than the shim. Older heads copy only that old path from new bases. Once every supported base includes this PR, contract in order: move the implementation to `scripts/fractal-test`, add the old `scripts/st-test` fallback to base readers, then delete `scripts/st-test` and the bridge marker. Preserve evidence/report/run-ledger paths and `ST_*` settings. See [the bridge contract](docs/st3/gate-evidence.md#running-the-checks-locally-scriptsfractal-test).

A push from an agent (`ST_AGENT` set, or no terminal) waits at most 300 seconds (`ST_EVIDENCE_AGENT_LIMIT`) for the hook, then goes, and signing continues in the background (log under `~/.local/state/st3/evidence-prepush/`); an interactive push waits up to 20 minutes (`ST_EVIDENCE_TIME_LIMIT`). Each note is pushed as soon as its check is signed, so one signed within the wait reaches the remote before the branch does. With `ST_SKIP_EVIDENCE=1` the push does not wait: the same signing runs in the background, and a CI run that starts before a note is there runs that check in full. With `ST_EVIDENCE_LOCAL=off` the hook does no local signing work at all (for a seat or unit where local builds are fenced), and `git push --no-verify` skips the hook entirely. `scripts/fractal-test --status` says whether a tree is covered. A new tree is always the slow path (the checks run once); a fixup that changes the tree is too; a push of a tree that already has notes is silent and instant. See [docs/st3/gate-evidence.md](docs/st3/gate-evidence.md), "Running the checks locally" and "Host keys".

**A machine with no evidence signer** (no `~/.config/st/evidence-sign.json`): hosted CI at the exact head is the proof. Push with `ST_SKIP_EVIDENCE=1 git push` and say in the pull request that you did; the evidence hook tells you this once per machine and is quiet after that. Missing signing configuration never blocks a push; the separate content guard still must pass. Evidence signing and any landing-signing transition remain separate from this content policy and are unchanged here.

The hook, `scripts/fractal-test` and `scripts/ci-genie-freshness` drop the `GIT_*` variables that select a repository or an identity (`GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_AUTHOR_*`, ...) before they start anything: git exports `GIT_DIR` to a hook run from a linked worktree, and a script that kept it would act on your repository when it meant a temporary one (st2#3014). Transport and credential variables (`GIT_SSH_COMMAND`, `GIT_ASKPASS`, ...) are kept.
